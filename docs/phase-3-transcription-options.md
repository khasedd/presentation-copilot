# Phase 3 — Transcription-component investigation

Investigated September 27, 2026. This is a bounded provider-selection record for the first realistic live-transcription proof of concept (POC). It does not implement a provider, capture microphone audio, provision infrastructure, or complete Phase 3. Transcript schema 1.0 remains unchanged because the documented provider behavior below does not demonstrate a concrete incompatibility.

## Decision

Use **Deepgram Nova-3 monolingual streaming provisionally for the first live POC**, with `interim_results=true`, 16 kHz mono `linear16`, 20–100 ms audio chunks, an explicit endpointing value selected during the trial, and `mip_opt_out=true`.

This is a POC selection, not a production commitment. It is the shortest path to measuring the Phase 3 risks: real interim revisions, finalization, word timing, microphone behavior, latency, accuracy, and a dropped WebSocket. The public pay-as-you-go offer currently includes a $200 credit without a credit card, and the current promotional Nova-3 monolingual streaming rate is $0.0048/minute. The documented Python SDK and WebSocket API avoid provisioning a GPU service before the transcription contract has been exercised with live audio.

NVIDIA Speech NIM with Parakeet remains the preferred later **deployment candidate** if an NVIDIA AI Enterprise (NVAIE) entitlement and approved Nebius GPU budget are available. It has the cleanest hackathon alignment, but NVIDIA documents NVAIE as required for self-hosting Speech NIMs. A Nebius L40S currently starts at $1.55/GPU-hour, before any software-entitlement question. Provisioning that stack to answer basic capture and adapter questions is disproportionate for this slice.

The official hackathon rules require the application to run on Nebius Token Factory or Nebius AI Cloud and use an NVIDIA open-source model; they do not require ASR itself to run there. The project's existing runtime Token Factory/Nemotron path remains substantive. Deepgram therefore neither supplies nor replaces the required Nebius/NVIDIA path. See the [official rules](https://nebiusglobalaihackathon.devpost.com/rules).

## Why the existing contract survives this investigation

Riva, Deepgram, and Google all expose tentative results that may change and settled results for an audio portion. The adapter can assign segment IDs, zero-based indices, consecutive event sequences, and revisions. Provider timestamps are evidence for `start_ms`/`end_ms`; provider connection boundaries map to internal stream boundaries. No provider requires downstream code to consume its native IDs or callback shape.

Deepgram's documented shorter-final example is the sharpest case. A provisional segment may initially cover 0–9.1 seconds, then be revised to a final 0–8.49 seconds while a new provisional segment begins at 8.49 seconds. Schema 1.0 already permits corrected offsets/text on the first segment followed by a new segment. The POC must prove this normalizer against observed messages. If live evidence instead shows a finalized segment later being split, merged, or withdrawn, that would be concrete evidence to revisit the contract.

## Unknowns that require live testing

1. Whether the available Deepgram account receives the documented free credit, permits `mip_opt_out`, and exposes the current Nova-3 streaming API without a billing action.
2. Which local microphone devices are visible, which one the user intends to use, whether the OS grants capture permission, its native channel count/sample rate, and whether client resampling is needed.
3. End-to-end interim and final latency from this network and machine; the provider's published typical latency is not project evidence.
4. Accuracy for the presenter's accent, pace, far-field distance, background noise, slide terminology, names, numbers, and self-corrections.
5. Actual interim churn, empty-result behavior, final-span shortening, punctuation changes, and whether every observed callback can be normalized without a rejected contract transition.
6. Endpointing behavior during rhetorical pauses and long continuous speech, plus graceful close behavior and the time required to flush remaining finals.
7. Behavior on an induced WebSocket loss: error timing, audio lost while reconnecting, buffer growth, timestamp realignment, and whether 1.25× replay is adequate.
8. Whether word timestamps are monotonic and accurate enough for segment offsets. Deepgram explicitly says they are not millisecond-precision latency clocks.
9. Whether a request/usage record confirms `mip_opt_out=true` without exposing transcript content. Application logs must also be inspected for accidental audio/text retention.
10. Speaker diarization quality and label stability. It is available but excluded from the first POC to isolate transcription; `speaker_id=None` is valid.

## Next bounded POC acceptance test

The next slice should add only an experimental Deepgram adapter/capture harness and tests for its normalization. It must not feed coverage, control Slides, advance slides, or add UI.

Use one explicitly selected microphone and 16 kHz mono `linear16`. Keep audio in memory only, enable `mip_opt_out=true`, disable diarization, and record safe measurements plus normalized event JSON in an ignored local output directory. Do not record raw audio by default. Pin the SDK version used by the experiment.

Run three bounded trials totaling no more than ten billable minutes:

1. A 90-second near-field scripted presentation containing at least 100 reference words, ten technical terms/names, numbers, pauses, a hesitation, and a spoken self-correction.
2. The same script at realistic presentation distance with ordinary room noise.
3. A 60-second failure trial that intentionally interrupts the WebSocket once, then starts a new internal stream; do not attempt cross-stream transcript reconciliation in this slice.

The POC passes only if all of the following are true:

- Every accepted provider callback normalizes through `TranscriptAccumulator` with consecutive internal counters, stable first-observed segment indices, no final-to-partial transition, and no mutation of the transcript contract.
- Concatenated internal final text exactly matches the provider's ordered final transcript for each uninterrupted stream; unfinished text stays partial at closure rather than being promoted.
- At least one real partial revision is observed and preserved in the captured event evolution. Any shorter-final/new-remainder case is normalized as documented above or reported as a blocking incompatibility.
- Near-field final word error rate is at most 15% and technical-term recall is at least 90%; distance/noise final word error rate is at most 25% and technical-term recall is at least 80%. These are POC continuation thresholds, not production claims.
- Measured p95 interim transcript lag is at most 1.0 second and p95 final availability is at most 2.5 seconds after the relevant spoken span/pause. Report p50/p95, chunk size, endpoint setting, device, network context, and sample count. Use the sent-audio cursor for transcript lag; do not treat provider word timestamps as a precision wall clock.
- The induced disconnect produces an explicit degraded/failed status and failed or cancelled stream closure; the new connection uses a fresh `stream_id`; no missing text is invented and no old-stream event is accepted by the new accumulator.
- The application stores no raw audio, prints/logs no transcript content, commits no live output or credential, and the provider request record confirms model-improvement opt-out. Sanitized aggregate measurements may be documented.
- The full existing repository test suite passes before and after, and focused adapter tests cover observed interim-to-final, shorter-final/new-remainder, empty-result, close, and error callbacks without network access.

Failure of an accuracy or latency threshold rejects this configuration, not the provider category forever. A contract-transition failure is stronger evidence: preserve the sanitized callback shape and decide explicitly whether the adapter policy or schema must change before continuing.
