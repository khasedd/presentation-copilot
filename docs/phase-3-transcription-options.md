# Phase 3 — Transcription-component investigation

Investigated September 27, 2026. This began as the bounded provider-selection record for the first realistic live-transcription proof of concept (POC). The subsequent implementation/preflight evidence below now records the experimental adapter, in-memory microphone path, authenticated handshake, and transport-only reconnect check. The three scored presentation trials remain pending, so this work does not complete Phase 3. Transcript schema 1.0 remains unchanged.

## Decision

Use **Deepgram Nova-3 monolingual streaming provisionally for the first live POC**, with `interim_results=true`, 16 kHz mono `linear16`, 20–100 ms audio chunks, an explicit endpointing value selected during the trial, and `mip_opt_out=true`.

This is a POC selection, not a production commitment. It is the shortest path to measuring the Phase 3 risks: real interim revisions, finalization, word timing, microphone behavior, latency, accuracy, and a dropped WebSocket. The public pay-as-you-go offer currently includes a $200 credit without a credit card, and the current promotional Nova-3 monolingual streaming rate is $0.0048/minute. The documented Python SDK and WebSocket API avoid provisioning a GPU service before the transcription contract has been exercised with live audio.

The [fixed-budget addendum](#fixed-budget-nebiusnvidia-addendum) below updates the later-deployment ranking: open Parakeet/NeMo is the preferred **NVIDIA challenger**, while Speech NIM remains a later deployment candidate conditional on verified entitlement. Neither is a deployment commitment. The $100 Cloud limit makes bounded runtime and judge access decisive; it does not rule out NVIDIA ASR technically.

The official hackathon rules require the application to run on Nebius Token Factory or Nebius AI Cloud and use an NVIDIA open-source model; they do not require ASR itself to run there. The project's existing runtime Token Factory/Nemotron path remains substantive. Deepgram therefore neither supplies nor replaces the required Nebius/NVIDIA path. See the [official rules](https://nebiusglobalaihackathon.devpost.com/rules).

## Why the existing contract survives this investigation

Riva, Deepgram, and Google all expose tentative results that may change and settled results for an audio portion. The adapter can assign segment IDs, zero-based indices, consecutive event sequences, and revisions. Provider timestamps are evidence for `start_ms`/`end_ms`; provider connection boundaries map to internal stream boundaries. No provider requires downstream code to consume its native IDs or callback shape.

Deepgram's documented shorter-final example is the sharpest case. A provisional segment may initially cover 0–9.1 seconds, then be revised to a final 0–8.49 seconds while a new provisional segment begins at 8.49 seconds. Schema 1.0 already permits corrected offsets/text on the first segment followed by a new segment. The POC must prove this normalizer against observed messages. If live evidence instead shows a finalized segment later being split, merged, or withdrawn, that would be concrete evidence to revisit the contract.

## Unknowns that require live testing

1. Whether the available Deepgram account receives the documented free credit, permits `mip_opt_out`, and exposes the current Nova-3 streaming API without a billing action.
2. Which local microphone devices are visible, which one the user intends to use, whether the OS grants capture permission, its native channel count/sample rate, and whether client resampling is needed.
3. End-to-end interim and final latency from this network and machine; the provider's published typical latency is not project evidence.
4. Accuracy for the presenter's accent, pace, far-field distance, background noise, slide terminology, names, numbers, and self-corrections.
5. Actual interim churn, empty-result behavior, final-span shortening, punctuation changes, and whether every observed callback can be normalized without a rejected contract transition.
6. Endpointing behavior during rhetorical pauses and long continuous speech, plus graceful close behavior and the time required to flush remaining finals.
7. Behavior on an induced WebSocket loss: error timing, audio lost while reconnecting, buffer growth, timestamp realignment, and whether 1.25× replay is adequate.
8. Whether word timestamps are monotonic and accurate enough for segment offsets. Deepgram explicitly says they are not millisecond-precision latency clocks.
9. Whether a request/usage record confirms `mip_opt_out=true` without exposing transcript content. Application logs must also be inspected for accidental audio/text retention.
10. Speaker diarization quality and label stability. It is available but excluded from the first POC to isolate transcription; `speaker_id=None` is valid.

## Next bounded POC acceptance test

The next slice should add only an experimental Deepgram adapter/capture harness and tests for its normalization. It must not feed coverage, control Slides, advance slides, or add UI.

Use one explicitly selected microphone and 16 kHz mono `linear16`. Keep audio in memory only, enable `mip_opt_out=true`, disable diarization, and record safe measurements plus normalized event JSON in an ignored local output directory. Do not record raw audio by default. Pin the SDK version used by the experiment.

Run three bounded trials totaling no more than ten billable minutes:

1. A 90-second near-field scripted presentation containing at least 100 reference words, ten technical terms/names, numbers, pauses, a hesitation, and a spoken self-correction.
2. The same script at realistic presentation distance with ordinary room noise.
3. A 60-second failure trial that intentionally interrupts the WebSocket once, then starts a new internal stream; do not attempt cross-stream transcript reconciliation in this slice.

The POC passes only if all of the following are true:

- Every accepted provider callback normalizes through `TranscriptAccumulator` with consecutive internal counters, stable first-observed segment indices, no final-to-partial transition, and no mutation of the transcript contract.
- Concatenated internal final text exactly matches the provider's ordered final transcript for each uninterrupted stream; unfinished text stays partial at closure rather than being promoted.
- At least one real partial revision is observed and preserved in the captured event evolution. Any shorter-final/new-remainder case is normalized as documented above or reported as a blocking incompatibility.
- Near-field final word error rate is at most 15% and technical-term recall is at least 90%; distance/noise final word error rate is at most 25% and technical-term recall is at least 80%. These are POC continuation thresholds, not production claims.
- Measured p95 interim transcript lag is at most 1.0 second and p95 final availability is at most 2.5 seconds after the relevant spoken span/pause. Report p50/p95, chunk size, endpoint setting, device, network context, and sample count. Use the sent-audio cursor for transcript lag; do not treat provider word timestamps as a precision wall clock.
- The induced disconnect produces an explicit degraded/failed status and failed or cancelled stream closure; the new connection uses a fresh `stream_id`; no missing text is invented and no old-stream event is accepted by the new accumulator.
- The application stores no raw audio, prints/logs no transcript content, commits no live output or credential, and the provider request record confirms model-improvement opt-out. Sanitized aggregate measurements may be documented.
- The full existing repository test suite passes before and after, and focused adapter tests cover observed interim-to-final, shorter-final/new-remainder, empty-result, close, and error callbacks without network access.

Failure of an accuracy or latency threshold rejects this configuration, not the provider category forever. A contract-transition failure is stronger evidence: preserve the sanitized callback shape and decide explicitly whether the adapter policy or schema must change before continuing.

## Implementation and preflight evidence — September 27, 2026

The POC branch adds a provider boundary in `transcription/adapters/deepgram.py` and a bounded experiment in `experiments/deepgram_live.py`. Provider dictionaries stop at the adapter. The adapter creates stream/segment IDs, first-observed indices, consecutive sequences and revisions; converts provider seconds to integer milliseconds; applies every normalized event through `TranscriptAccumulator`; treats empty metadata/speech-boundary/results callbacks as no-ops; emits explicit failed status and closure; and creates a new adapter/accumulator for reconnect. A shorter final deterministically finalizes the settled span and creates a timed partial remainder from the prior word timings. If a tentative word crosses the authoritative final boundary, the remainder starts at that boundary. The parser also accepts ordinary provider word-time overlap, falls back to raw `word` when `punctuated_word` is empty, and clips independently rounded one-millisecond word/result boundary drift. Missing usable remainder timing or drift beyond that narrow tolerance raises a sanitized blocking incompatibility instead of changing schema 1.0.

The experiment uses the documented lower-level WebSocket API rather than the Deepgram SDK. Its only added dependency is exactly pinned `websockets==15.0.1` (BSD-3-Clause). The listen request uses Nova-3 monolingual English, `interim_results=true`, `mip_opt_out=true`, 16 kHz mono `linear16`, 50 ms chunks, `endpointing=500`, punctuation/smart formatting, and VAD events; no diarization parameter is sent. `parec` requests the transmitted format from PipeWire-Pulse, which performs the required conversion from the selected microphone's 48 kHz stereo native path. Raw PCM remains in the capture/WebSocket pipes and process memory. Only aggregate metrics are eligible for the ignored `deepgram-output/` directory; recognized text, reference text, provider bodies, raw audio, and credentials are not written or printed.

Host diagnosis established that the initial sandbox-only `arecord` failure was not a host audio failure. Outside the restricted execution sandbox, PipeWire 1.6.7, PipeWire-Pulse, and WirePlumber were active; `/dev/snd` exposed the Realtek ALC294 capture device with an ACL for the current user; and the default, unmuted source was `alsa_input.pci-0000_63_00.6.analog-stereo`. A two-second in-memory PipeWire-Pulse capture produced nonzero 48 kHz stereo signed-16 PCM without persisting audio. The scored trial path requests 16 kHz mono signed-16 PCM from that source.

Credential/account findings are deliberately categorical. The ignored `.env` contains a nonempty `DEEPGRAM_API_KEY`. `GET /v1/projects` and `GET /v1/models` succeeded, and the authenticated catalog exposed English Nova-3 streaming. `POST /v1/auth/grant` returned 403 because this key lacks the higher token-grant scope; project balance/purchase endpoints also returned 403, so exact balance, credit origin, and expiry remain unknown and are not documented as account facts. No billing action was taken. A real two-second WebSocket preflight accepted the full request including `mip_opt_out=true`, processed 1.8 provider-reported seconds, and returned metadata. This proves current core API access and usable service credit without enabling billing; it proves that the request parameter was accepted, but not an independently retrievable provider request record.

A separate six-second transport-only preflight intentionally interrupted the first connection and opened a second. It recorded an explicit failed boundary, distinct stream IDs, a fresh accumulator, and 5.6 provider/estimated billable seconds. It did not concatenate text or report cross-stream WER. After the deterministic timing fix, the current harness passed another two-second handshake with 1.6 provider-reported billable seconds and monotonic timestamps. A later 14.55-second content-free smoke run also completed. Completed aggregate reports total 23.55 billable seconds with an estimated Nova-3 cost of $0.001884 at the committed $0.0048/minute baseline. Failed stream usage is not available to this key and is excluded from that exact subtotal. These runs validate connectivity and failure mechanics, not the required spoken Trial A, B, or C evidence.

Three attempted Trial A reads reached real speech but stopped before producing valid aggregate evidence. In order, they exposed a legitimate final ending slightly before a longer interim with no timed remainder, a final boundary crossing the first tentative remainder word, and provider word metadata containing overlap/empty punctuation/one-millisecond rounding variance. Each shape was reduced to a deterministic regression before the adapter policy changed. Failed-run cleanup removed the reserved output each time, and no transcript or reference text was retained. The attempts therefore establish real callback compatibility findings only; they do not establish WER, term recall, latency, endpointing, or a passed Trial A.

**Actual partial/final behavior (D):** NVIDIA's [NeMo Voice Agent STT documentation](https://docs.nvidia.com/nemo/labs-voice-agent/about/core-concepts/speech-pipeline/speech-recognition/) describes persistent encoder caches and partial text before speech stops. With the EOU model, the STT stage emits interim frames; a downstream turn-taking stage strips EOU/EOB and promotes buffered text to final. For the non-EOU model it uses a wrapper `is_final` flag plus VAD turn boundaries. Missing EOU at a VAD stop can reset the cache. These are wrapper policies, not a promise of immutable finals from raw weights. We would reuse only the relevant ASR logic, not deploy the voice agent's LLM/TTS/UI stack.

**Serving and contract fit (I/U):** own audio framing/resampling, per-connection caches, serialized decoding, whole-hypothesis replacements, EOU/VAD finalization, end-of-stream flush, queue limits, authentication/TLS, errors and shutdown. The Python client still captures locally; a cloud GPU cannot directly access the presenter's microphone. Emit revisions until an explicit endpoint/flush settles an utterance; strip control tokens. Timestamp availability/accuracy for incremental decoding is unverified: use both segment offsets as null until established, never substitute callback time for acoustic time. Assign monotonic observation times/counters and fresh stream IDs on reconnect; retain incomplete partials and report lost audio. This fits `TranscriptEvent` 1.0 without redesign, but does not yet prove the timing acceptance gate. One presenter uses `speaker_id=None`; no diarization is needed.

**Hardware/performance (I/U):** neither shortlisted open model card gives an ASR-only minimum VRAM or a measured L40S real-time factor. FP32 parameter storage alone is approximately 0.48 GB/2.4 GB for 120M/600M; that is not peak runtime memory. Their hardware lists name Volta/Ampere/Hopper/Blackwell, not Ada L40S explicitly. L40S 48 GB is a plausible CUDA target requiring verification. A listed Blackwell-family alternative is Nebius RTX PRO 6000 96 GB at $1.80/hour; driver/runtime compatibility remains a test. Do not silently substitute H100 if L40S is unavailable. Require sustained processing faster than incoming audio, bounded caches, and the existing end-to-end latency thresholds; chunk duration/vendor EOU latency is not total latency or an RTF measurement. CPU-only may eventually be cheaper but has no qualifying project streaming measurement, so is not the cost baseline.
